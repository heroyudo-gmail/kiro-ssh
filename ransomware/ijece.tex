\begin{abstract}
\vspace{.3em}
Ransomware attacks pose a serious threat to data availability and integrity in cloud-based storage environments. However, conventional backup systems remain vulnerable when backup repositories are directly accessible from the primary system, while single-algorithm compression methods are often inefficient for heterogeneous file types. This study proposes a cloud-based backup system that integrates an air-gapped backup mechanism with adaptive multi-algorithm lossless compression to improve data resilience and storage efficiency. The system employs SHA-256 hash verification, metadata analysis, and file structure analysis to distinguish legitimate backup encryption from ransomware-induced file modifications. Experimental evaluations were conducted under normal and ransomware-simulated conditions using various file types and sizes. The results show that Zstandard achieved a compression ratio of 70--80\% for large files, while Snappy and LZ4 provided faster processing times of 0.5--2 seconds. The proposed system successfully restored all 113 affected files without recovery errors and achieved 0\% False Positive Rate (FPR) and 0\% False Negative Rate (FNR). Overall, the proposed approach effectively enhances the security, resilience, and storage efficiency of cloud-based backup systems against ransomware threats.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
The rapid development of digital technology over the past decade has significantly transformed various sectors, particularly the financial sector. Financial digitalization is no longer limited to transaction processing but also encompasses data recording, reporting, risk monitoring, and real-time analytics \cite{1}, \cite{2}. This significant increase in data volume requires organizations to manage large-scale data storage securely and efficiently, especially in the face of growing cybersecurity threats \cite{3}, \cite{4}. This transformation has led to an exponential increase in data volume, including daily transaction records, system logs, user data, financial reports, and audit documents \cite{5}. Financial institutions are estimated to process millions of transactions daily, generating hundreds of gigabytes to terabytes of data that must be securely archived for long-term operational needs, auditing, and regulatory compliance. Therefore, organizations require data storage systems that are both secure and efficient, along with backup mechanisms capable of ensuring data availability and integrity.

One of the most significant cybersecurity threats to modern organizations is ransomware, a type of malware that encrypts victims' data and demands ransom payments to restore access \cite{5}, \cite{6}. Modern ransomware attacks are increasingly sophisticated because they not only target production systems but also compromise connected backup infrastructures \cite{7}, \cite{8}. When backup systems are infected, organizations may lose the ability to recover critical data, resulting in operational disruption, financial losses, and reputational damage \cite{9}. According to the Sophos State of Ransomware in Financial Services 2024 report, approximately 43\% of devices in financial organizations were affected by ransomware incidents. Consequently, conventional connected backup systems are no longer sufficient to provide reliable protection. One effective mitigation strategy is the implementation of an air-gapped backup architecture, where backup storage is physically or logically isolated from the primary network, preventing ransomware from directly accessing backup data \cite{10}. However, implementing a fully physical air-gapped infrastructure is often costly and operationally complex for small and medium-sized organizations, particularly in developing countries. Therefore, this study adopts a logical air-gapped approach using controlled mounting and isolated backup media to provide practical ransomware resilience while maintaining operational feasibility and lower deployment cost. The proposed approach prioritizes affordability, ease of deployment, and compatibility with existing cloud-based infrastructures commonly used by local organizations and financial institutions.

Besides security challenges, storage efficiency has also become a major concern due to the continuous growth of archival data volume. Cold cloud storage has emerged as a widely adopted solution for storing infrequently accessed data such as transaction logs, audit records, and system backups because of its lower operational cost \cite{11}. However, storing large-scale backup data in cloud environments still requires efficient storage optimization and bandwidth management. Lossless compression techniques are commonly used to reduce storage consumption while preserving data integrity \cite{12}, \cite{13}. Nevertheless, previous studies generally focus on backup security, ransomware mitigation, or compression techniques independently, resulting in limited integration between secure backup architectures and adaptive storage optimization mechanisms \cite{14}, \cite{15}. Furthermore, most existing systems utilize a single static compression algorithm, despite the fact that different file types and data sizes exhibit varying compression characteristics and performance trade-offs \cite{16}, \cite{17}.

Unlike prior studies that primarily rely on static compression methods or separate backup protection mechanisms, this research proposes an integrated cloud backup system that combines an air-gapped storage architecture with an adaptive multi-compression algorithm framework. The proposed system dynamically selects among five lossless compression algorithms---Gzip, Zstandard, Brotli, LZ4, and Snappy---using a rule-based adaptive selection mechanism based on file characteristics such as file size and data type to optimize compression ratio, processing speed, and resource utilization. In addition, this study uniquely integrates multi-indicator anomaly detection mechanisms consisting of SHA-256 hash analysis, metadata validation, and file structure inspection to distinguish ransomware encryption behavior from legitimate AES-256 encryption activity within the cloud backup environment. This capability addresses an important limitation in previous studies, where encrypted files are often treated uniformly without differentiating malicious encryption from authorized security encryption processes.

Therefore, this study contributes an integrated approach that simultaneously addresses ransomware resilience, backup isolation, adaptive compression efficiency, and integrity verification within a single cloud-based backup framework. By combining air-gapped architecture, adaptive multi-algorithm compression, AES-256 encryption, SHA-256 integrity verification, and multi-indicator anomaly detection, the proposed system is expected to improve both backup security and long-term storage efficiency for financial data infrastructures in cloud environments \cite{18}, \cite{19}, \cite{20}.

\section{Method}
\label{sec:method}
This study employs a quantitative experimental design to evaluate the performance of a cloud-based backup system integrating multiple lossless compression algorithms \cite{22}, \cite{23}, \cite{24}, \cite{25}. Each algorithm is tested independently in a single-mode configuration with evaluation parameters including storage efficiency, processing time, and resilience against simulated ransomware attacks. The proposed system adopts a hybrid air-gapped backup architecture that combines offline local storage and cloud storage \cite{26}, \cite{27}. The experimental environment is designed to resemble real-world financial information systems, characterized by large-scale data storage requirements and long-term retention, while also incorporating ransomware detection and mitigation aspects as discussed in previous studies \cite{28}, \cite{29}.

\subsection{System architecture}
The proposed system architecture is organized into three logical layers that support backup, compression, and detection processes \cite{30}. At the application layer, the system manages file upload, backup, and restore operations. Each incoming file undergoes cryptographic hash computation using the SHA-256 algorithm, metadata extraction, and structural file analysis to establish an integrity baseline. This information is stored as a reference to detect future file changes and to distinguish between legitimate modifications (e.g., backup or normal encryption) and malicious alterations caused by ransomware activities.

At the protection and compression layer, the system performs initial metadata inspection to detect potential anomalies. Files are then secured using AES-256 encryption to ensure data confidentiality. After encryption, files are compressed using five lossless compression algorithms: Gzip, Zstandard (Zstd), Brotli, LZ4, and Snappy \cite{31}. Each algorithm is applied independently to the same dataset to obtain empirical measurements, including compression ratio and processing time, enabling consistent performance comparison \cite{32}.

At the storage and detection layer, encrypted and compressed files are stored in an air-gapped environment to ensure physical isolation from production networks and enhance resilience against ransomware attacks. Additionally, backup data are synchronized to cloud storage via the Google Drive API for redundancy. Critical metadata, including file size, processing time, and SHA-256 hash values, are recorded for performance analysis, integrity verification, and anomaly detection. When ransomware activity is detected, the system automatically initiates a restore process from air-gapped storage, followed by decompression and AES-256 decryption to recover files to their original state.

No real financial or confidential production data were used in this study to maintain data privacy and confidentiality compliance \cite{34}.

\subsection{AES-256 encryption and decryption implementation}
To ensure data confidentiality, the system implements the Advanced Encryption Standard (AES) with a 256-bit key as a symmetric encryption algorithm. During the backup process, the original file (plaintext) is encrypted using an AES-256 secret key, producing unreadable ciphertext. The encrypted file is then compressed and stored in both air-gapped and cloud storage. During the restore process, the file is retrieved from storage, followed by decompression and decryption using the same key to convert ciphertext back into plaintext. Data integrity is subsequently verified using SHA-256 hashing to ensure no corruption or unauthorized modification has occurred.

\subsection{Compression algorithm implementation}
The adaptive compression mechanism implemented in this study uses a rule-based selection strategy rather than machine learning. Compression algorithms are automatically selected based on file type and file size characteristics identified during preliminary testing. Small text-based files such as LOG and TXT are primarily assigned to Snappy or LZ4 due to their processing speed and low computational overhead. Large structured files such as CSV and XLSX are processed using Zstandard to achieve higher compression ratios for long-term storage efficiency. Meanwhile, already compressed binary files such as JPG are processed using lightweight algorithms to minimize unnecessary compression overhead and execution time.

System implements five open-source lossless compression algorithms Gzip, Zstandard, Brotli, LZ4, and Snappy to evaluate their performance in a cloud-based backup environment \cite{36}. Gzip is selected for its wide compatibility, while Zstandard and Brotli are utilized for their high compression ratios. In contrast, LZ4 and Snappy are employed due to their high processing speed and low latency characteristics \cite{37}. The implementation is developed in Python, where each dataset file is compressed independently using all five algorithms under identical experimental conditions \cite{38}. Performance evaluation includes compression ratio and processing time measurements to provide a comprehensive analysis of storage efficiency and computational performance \cite{39}, as well as implementation flexibility for hybrid edge-cloud backup systems \cite{40}.

\subsection{Backup and restore procedures}
Backup process begins with SHA-256 hash computation to establish a data integrity baseline. Files are then encrypted using AES-256 to ensure confidentiality, followed by compression using the selected lossless algorithm. The resulting files are temporarily stored in an air-gapped directory before being transferred to cloud storage. In addition to the air-gapped mechanism, a mirroring strategy is implemented to enhance data availability and recovery readiness. Under normal conditions, when no anomalies or ransomware indicators are detected based on hash and metadata verification, the system terminates after completing the backup process without initiating restoration. This approach minimizes unnecessary recovery operations and reduces system overhead.

Restore process is triggered only when anomalies are detected, such as hash mismatches, metadata inconsistencies, or indications of unauthorized encryption. In such cases, data are retrieved from air-gapped storage, decompressed, and decrypted to restore the original files. The recovered files are then validated by comparing their hash values with the reference baseline.

\subsection{Ransomware attack simulation}
To evaluate the resilience of the proposed backup system, a ransomware attack simulation was conducted without executing actual malware. This simulation was based on real-world vulnerability patterns, including CVE-2017-0144, which represents an encrypt-and-hold attack model; CVE-2021-36934, which simulates file overwriting and corruption behavior; and CVE-2018-8453, which targets file metadata and header structure. In each scenario, file modifications were carried out in a controlled manner to mimic ransomware-induced damage. The objective of this simulation is to assess the system's ability to detect anomalies and to recover affected files from air-gapped backups.

\subsection{Ransomware detection and encryption differentiation mechanism}
In modern cloud systems, files may undergo legitimate compression and encryption processes, requiring differentiation from ransomware-induced encryption. The detection mechanism in this study combines SHA-256 hash verification, metadata analysis, and air-gapped backup validation. Each file's hash is computed as an integrity baseline and re-verified during inspection to detect unauthorized changes. Additionally, metadata consistency such as file size, modification time, file type, and extension is analyzed alongside structural file characteristics to identify abnormal changes inconsistent with legitimate AES-256 encryption or compression processes.

If discrepancies are detected between primary storage and air-gapped backup copies, the system classifies the condition as a potential compromise. Based on hash, metadata, and backup validation results, files are categorized into normal condition, legitimate modification, or ransomware indication, enabling early detection and secure data recovery.

\subsection{Performance evaluation metrics}
The performance of the proposed cloud-based backup system with multi-algorithm compression is evaluated through quantitative experimental analysis. Several metrics are used to assess storage efficiency, processing performance, data integrity, and system resilience. Compression Ratio (CR) is defined as:

\begin{equation}
CR = \frac{S_{after}}{S_{before}}
\end{equation}

where $S_{before}$ represents the file size before compression and $S_{after}$ represents the file size after compression. Compression Factor (CF) indicates how many times the original data size is reduced after compression and is the inverse of the compression ratio. A higher CF value indicates better compression efficiency:

\begin{equation}
CF = \frac{S_{before}}{S_{after}}
\end{equation}

Storage Saving Percentage (SS) is used to measure the percentage of storage space saved after compression, which is particularly important in long-term cloud storage scenarios:

\begin{equation}
SS = \frac{S_{before} - S_{after}}{S_{before}} \times 100\%
\end{equation}

To comprehensively evaluate compression algorithm efficiency, this study introduces a combined efficiency score ($E$) that integrates storage efficiency and compression time efficiency. This score is calculated using a Multi-Criteria Decision Making (MCDM) approach with the Weighted Sum Model (WSM), formulated as:

\begin{equation}
E = \alpha (1 - R) + \beta \left( \frac{1}{T} \right)
\end{equation}

where $R$ denotes the compression ratio, with $(1-R)$ representing storage efficiency, and $T$ represents compression time in seconds, with $1/T$ indicating processing time efficiency. The parameters $\alpha$ and $\beta$ are weighting factors that control the contribution of each component, set to $\alpha = 0.5$ and $\beta = 0.5$ to ensure a balanced evaluation between storage efficiency and processing speed. To enable relative comparison among algorithms, the combined efficiency score is normalized as follows:

\begin{equation}
E(\%) = \frac{E}{E_{max}} \times 100
\end{equation}

The interpretation of the combined efficiency score is based on the performance classification shown in Table~\ref{tab:efficiency_criteria}.

\begin{table}[H]
\centering
\fontsize{8pt}{10pt}\selectfont
\caption{Criteria for interpreting system efficiency score}
\label{tab:efficiency_criteria}
\begin{tabularx}{\textwidth}{@{}c c X@{}}
\hline
\textbf{Score (\%)} & \textbf{Status} & \textbf{Description} \\
\hline
$\geq 90$ & Excellent & Very high performance in both storage efficiency and processing speed \\

In addition to compression efficiency metrics, this study also evaluates system recovery performance as part of overall system resilience. The Recovery Time Objective (RTO) represents the total time required for the system to restore normal operation after a ransomware attack is detected:

\begin{equation}
RTO = T_{recovery} - T_{incident}
\end{equation}

where $T_{incident}$ is the time when the ransomware attack is identified, and $T_{recovery}$ is the time when the system has fully recovered. A lower RTO indicates faster recovery performance and higher system resilience. To evaluate the reliability of ransomware detection, this study also measures False Positive Rate (FPR) and False Negative Rate (FNR). These metrics are used to assess the capability of the system in distinguishing legitimate backup encryption activities from unauthorized ransomware-induced modifications. False Positive Rate (FPR) is defined as:

\begin{equation}
FPR = \frac{FP}{FP + TN} \times 100\%
\end{equation}

False Negative Rate (FNR) is defined as:

\begin{equation}
FNR = \frac{FN}{FN + TP} \times 100\%
\end{equation}

where FP represents False Positive cases, where normal files are incorrectly identified as ransomware; TN represents True Negative cases, where normal files are correctly identified as safe; FN represents False Negative cases, where ransomware-infected files are not detected; and TP represents True Positive cases, where ransomware-infected files are successfully detected. Lower FPR and FNR values indicate higher reliability of the detection mechanism and better system resilience against ransomware attacks.

All files maintained identical SHA-256 hash values, indicating zero data alteration. Zstandard achieved the highest compression efficiency, while Snappy and LZ4 provided the fastest processing time. During ransomware simulation, the air-gapped mechanism enabled 100\% successful recovery with zero errors, demonstrating strong system resilience.

\subsection{Implementation and structure of air-gapped backup storage}
As an additional layer of protection, the system implements an air-gapped backup mechanism using a separate storage medium in the form of an external SSD. This medium is not permanently accessed by the system but is only mounted during backup or restore processes. This approach aims to minimize the risk of unauthorized access and malware propagation through network channels. The air-gapped implementation used in this study is online (logical air-gapped backup), where the storage medium remains within the system environment through access control settings, active sessions, and limited mounting mechanisms. With this approach, the medium can only be accessed under specific conditions defined by the system, without an active network connection during the backup storage process.

Although the proposed logical air-gapped mechanism significantly reduces ransomware exposure, it does not provide the same level of isolation as a fully offline physical air-gapped infrastructure. Because the backup media is mounted temporarily during backup and recovery sessions, advanced malware capable of memory persistence or delayed execution may still attempt to access the mounted storage once it becomes available. However, this risk is mitigated through temporary mounting duration, automatic disconnection after backup completion, SHA-256 integrity verification, metadata validation, isolated backup repositories, and restricted access sessions. Therefore, the proposed architecture provides a practical and cost-effective ransomware resilience solution suitable for small and medium-sized organizations that may not have sufficient resources to deploy fully physical offline air-gapped infrastructures.

System automatically detects corrupted files during the restore process by comparing checksums before and after recovery. \subsection{Decompression, decryption, and data integrity validation and recovery time evaluation}
Data integrity validation is performed after the restore process to ensure that recovered files are identical to the original data before the attack. Files restored from the air-gapped medium are in encrypted and compressed form, so the system first performs decompression followed by decryption using the AES-256 algorithm and the corresponding secret key. After decryption, the system compares the SHA-256 checksum values of the file before restore (sha\_in) and after restore (sha\_out). A file is considered valid if both checksum values are identical, indicating that data integrity has been preserved throughout the backup and recovery process.

\section{Conclusion}
\label{sec:conclusion}
A cloud-based backup system integrating an air-gapped backup mechanism with multi-algorithm lossless compression was developed to improve resilience against ransomware attacks while optimizing storage efficiency. The system successfully performs compression, backup, anomaly detection, and automated data recovery within an integrated environment. Experimental results demonstrate that compression performance depends on data characteristics. Snappy and LZ4 provide faster processing times for small and medium-sized files, while Zstandard achieves the highest compression ratio, reaching up to 80\% storage savings for large CSV files.

Ransomware simulations using multiple attack scenarios, including CVE-2017-0144, CVE-2018-8453, and CVE-2021-36934, demonstrated that the proposed system successfully maintained data integrity and achieved a 100\% data recovery rate across all tested files through the air-gapped backup mechanism. In addition, the anomaly detection mechanism successfully detected unauthorized file modifications while maintaining zero false positives during normal AES-256 encryption operations. These findings indicate that integrating air-gapped backup architecture with multi-algorithm compression significantly enhances both system resilience and storage efficiency in cloud-based backup environments.

The adaptive compression mechanism currently utilizes a rule-based selection strategy due to its lower computational overhead, lightweight implementation, and faster decision-making capability for cloud backup environments requiring efficient resource utilization and rapid recovery response. This approach is considered suitable for financial cloud systems where reliability and low-latency operations are critical. Future work may enhance the current rule-based adaptive compression mechanism by incorporating machine learning approaches such as Random Forest to further optimize algorithm selection accuracy and scalability for larger and more heterogeneous datasets.
